## 2 分级与执行规则

| 等级 | 含义 | 运行条件 |
|---|---|---|
| L0 | 查询，不预期改变设备业务状态 | 只读环境；仍需核对线程局部副作用及响应规模 |
| L1 | 线程配置或隔离测试资源写入 | 固定通信线程、已登记的测试变量和程序槽 |
| L2 | 运动、使能、PLC、坐标映射、实际 I/O | 隔离台架、限速限位、独立停止手段、现场操作人员在场 |
| L3 | 全局删除、保存、复位、网络重配或广播 | 独占维护窗口、可恢复备份、明确的受影响设备清单 |

优先级 P0 为首轮及交付阻断项，P1 为适用功能验收项，P2 为扩展兼容项。等级与优先级独立；不能因 P0 就自动执行高影响命令。以下带 `{…}` 的文本均是模板，执行前替换；不是可直接批量粘贴的脚本。

执行遵循以下顺序：环境登记和备份 → L0 基线 → open/close/list 专项 → 测试变量 → 程序与 PLC → 台架运动 → 保存复位与总线 → 通信故障及恢复 → 恢复后核对。各组按自身前提执行；已存在运行程序、安全 PLC 或用户缓冲区时，不能为满足测试前提直接停用或清空它们。

一次请求分别记录三个结论：**协议完成**、**业务动作完成**、**测试环境已恢复**。收到 ACK 只能按该指令的手册语义认定协议边界；不等于运动到位、Flash 已落盘或程序已经完成。手册未定义的错误文案、未打开对象操作和断线后的缓冲区状态属于兼容性观察项，不预设统一错误码或事务回滚。

为 open/close/list 准备以下夹具，全部使用专用槽：

- **F-A 与 F-B**：同类程序的两个版本，分别包含能从 list 辨认的不同常量；不连接实际 I/O，不含运动和自动使能。
- **F-LINES**：至少 12 条可 list 的程序行，常量依次唯一；包含跳转标签及一行多语句，用来区分文本行号、命令偏移与 N 标签。注释或符号可能在编译后消失，不能据源文件物理行数直接判定 list 行数。
- **F-LONG**：根据内存预算生成足够大的无副作用程序，使响应跨多个 SSH 数据包和库内部缓冲区；不追求填满现场内存。
- **F-PC**：可稳定停在指定计算边界的专用程序，以及带调用层级的子程序版本。
- **F-KIN**：离线核对过的恒等或已知变换运动学夹具；只绑定隔离坐标系。
- **F-ROT**：已 define 的专用 rotary 缓冲区，含可区分的尚未计算行；记录分配大小及读取边界。

夹具中的程序体采用手册程序语言合法语句；其作用是驱动在线指令测试，不扩展为整个程序语言的验收。所有原始请求、原始响应和规范化 list 基准都要保留。

## 4 open close 专项

本节除特别说明外为 L1，所有固定缓冲区用例均在独占测试槽执行，`open` 到 `close` 固定在 A 线程；跨线程用例另行使用 B。每次失败后先判定缓冲区是否仍打开，再恢复，不能让后续探测被误编译成程序内容。

### O01 六类缓冲区完整生命周期  P0

依据：1278–1286。分别展开为六个子用例：`open prog {prog}`、`open plc {plc}`、`open subprog {sub}`、`&{c}open forward`、`&{c}open inverse`、`&{c}open rotary`。rotary 须先 define；PLC 须 disabled，subprog/运动学遵守 O05 的更强前提。

步骤：备份并确认前提 → A 打开指定缓冲区 → 逐行输入该类型合法夹具 → A 用正确坐标系执行 `close` → 从关闭状态执行对应 `list` 和 `buffer` 核对。

预期：全部输入归属正确对象，无跨类型、跨坐标系写入；关闭后得到预期程序语义。`buffer` 对适用的固定程序报告名称、offset、size，不能仅凭 `buffer` 代替 rotary 配置验证。恢复：删除专用夹具或恢复原内容。

### O02 打开立即覆盖旧内容  P0

依据：1279–1284、1286。对 prog/plc/subprog/forward/inverse 分别写入并关闭 F-A，保存 list 基准；重新 open 同一对象，写 F-B 后 close。

预期：新 list 仅为 F-B，不是追加，F-A 不应残留。再在 open 后注入非法行，按 O08 验证旧内容不会自动恢复。rotary 不套用固定缓冲区的覆盖判据，其行为另测 O13。恢复：依据备份重建，不能假设失败会保留 F-A。

### O03 空关闭与删除语义  P0

依据：1168–1169。对专用固定程序执行 `open prog {prog}` 后立即 `close`，并对 plc/subprog/forward/inverse 展开。用关闭后的 `buffer` 与 list 检查。

预期：固定程序对象被消除，不保留一个空缓冲区；不存在对象时的 list 具体回复另记 T09。对 prog/plc，再比较 `clear prog {prog}`、`clear plc {plc}` 的等价结果。恢复：重建夹具。rotary 结构保留规则见 O13。

### O04 跨线程及跨类型打开互斥  P0

依据：1279–1286。A 保持一个缓冲区打开；B 尝试打开同一对象、另一编号、另一类型、另一坐标系的缓冲区。各次试验独立初始化。

预期：手册要求的其他缓冲区已打开条件阻止 B 的 open，不能把全局互斥误实现为仅同类型互斥。B 的失败不应让输入偷偷归属 B；A 能继续写合法行并关闭。A 同线程嵌套 open 的错误恢复状态单独记录，若作为非法入缓冲行处理，按 O08 核对。恢复：由已确认的所有者关闭。

### O05 运行与暂停状态下打开限制  P0  L2

依据：1279–1286。用专用无物理输出程序分别建立 running、hold/quit/step 挂起和完全退出状态；测试目标 prog 的 open。对 PLC 建立 enabled、paused/step、disabled 状态测试 open plc。对 subprog/forward/inverse 测试任一运动程序运行或挂起、任一 PLC enabled 的组合。

预期：正在使用的固定 prog 即使只是挂起也拒绝重开；目标 PLC 必须 disabled，paused 不够；subprog 和运动学缓冲区要求无运动程序运行或可恢复挂起且无 PLC enabled。完全退出相关运动程序、禁用相关测试 PLC 后才能打开。不能把某个 prog 的限制扩大成所有 prog 必须停止的通用规则。恢复：专用程序完全退出并恢复测试 PLC 状态。

### O06 普通 close 的线程所有权  P0

依据：1169。A 打开固定程序并写入一行；B 发 `close`；A 继续写第二行并 close，再 list。

预期：B 的普通 close 不能关闭 A 打开的固定缓冲区，最终保留 A 两行。手册未规定这种跨线程无效操作的统一错误文案，原样记录。无缓冲区打开时，A 连续两次 close 应被接受且无动作。恢复：确认全局不再有测试缓冲区打开。

### O07 close all buffers 跨线程恢复  P0  L3

依据：1169。仅在不存在其他用户下载的隔离设备上：A 打开固定程序并写合法内容，B 发 `close all buffers`；之后 list 并尝试由 B 打开新的测试缓冲区。

预期：A 的固定缓冲区被关闭，已有合法内容可核对，新 open 不再因其占用而被拒绝；没有打开对象时该命令也接受且无动作。A 后续行的解释已回到在线状态，必须用无副作用哨兵验证。该命令关闭而非全局清空，不能替换成 `clear all buffers`。rotary 不在该段列举类型中，其跨线程恢复能力须单独实测，不预设支持。

### O08 非法输入清空并自动关闭  P0

依据：1279–1284、1286。固定缓冲区写若干合法行后，分别注入语法非法行和仅在线有效的指令；每个类型独立试验。保存首次错误响应，不在错误后盲目继续下载。

预期：该行被拒绝，已输入内容清空，缓冲区自动关闭；随后独立的在线只读哨兵能正常响应。用 buffer/list 核实没有部分程序被当作加载成功。rotary 的非法行处理不直接引用固定缓冲区规则。恢复：重新 open，从头完整写入夹具后 close。

### O09 在线执行与程序入缓冲的区别  P0

依据：1177、1233、1290–1291 及各 open 条目。A 在关闭状态将测试 P 变量置为基线；A open 后输入单变量赋值，B 查询该全局 P 变量；A close 后 list，再按测试程序方式执行。

预期：open 期间赋值进入程序，没有立即改变全局 P；执行夹具后才变为新值。另测多变量列表输入被拒绝及由此触发的固定缓冲区清空/关闭。L/R/D 程序局部空间与通信线程空间独立，不能用 A 在线局部变量值验证程序已执行。恢复：恢复 P 基线并清除夹具。

### O10 可选参数与编号边界  P1

依据：1278–1286。分别测试默认参数、仅 stack offset、跳过第一可选项的双逗号、同时给出 stack offset 和标签表大小；如 `open prog {prog},64`、`open prog {prog},,2048`、`open prog {prog},512,256`，在适用类型展开。

预期：默认 stack offset 为 256、标签容量 1024；合法参数生成能 list 和执行的夹具。PLC 边界 0/31、越界 -1/32；subprog 0 非法；prog 0 单独进入 O14；非整数/超 32 位编号及不足资源参数单独负测。有效极大编号只在具备资源的隔离设备验证，不把编号大小等同内存分配大小。恢复：确认失败后的开闭状态，归还资源。

### O11 运动学对象按坐标系隔离  P1  L2

依据：1278–1281。在 `{c}` 与 `{c2}` 分别加载不同 F-KIN；close 后，分别 `&{c}list forward`、`&{c2}list inverse` 及对应反向组合。

预期：同类型内容不串坐标系；forward 的 motor→axis 与 inverse 的 axis→motor 方向符合夹具；list 不触发运行。修改前完全退出所有测试运动程序并禁用测试 PLC。恢复：恢复两个坐标系原运动学及映射。

### O12 打开期间的 list 与其他线程查询  P0

依据：各 open 条目的非法输入规则、1235–1238。固定缓冲区打开期间，由 A 发仅在线有效的 list，按 O08 核对；另一次由 B 发 list/buffer/变量查询并记录读取状态。每次只做一个干扰操作。

预期：不得假定 A 的 list 可安全穿过下载上下文；若其被作为非法输入拒绝，应核实清空和自动关闭。B 的读取结果须明确是已关闭版本、当前编译态或错误；手册未承诺一致快照的部分做兼容性记录，不以读取部分内容当作下载成功。rotary 打开时的 list rotary 按 T07 应不满足前提。

### O13 rotary 的专有生命周期  P0  L2

依据：1183–1185、1168–1169、1284–1285、1238。未 define 时尝试 open；define 后 `&{c}open rotary`，写入 F-ROT；在 `{c}` 发 close；停止后执行 `clear rotary`，最后 `delete rotary`。

预期：未 define 时不能正常入缓冲；close 以被寻址坐标系为条件；clear 清内容但保留已分配结构并把程序指针置于开头，delete 才消除结构。clear 要求已关闭且运动程序完全退出，不能仅 hold/quit/step。跨线程 close、切换坐标系后 close 的行为分别记录，再返回正确坐标系清理；不能只套固定缓冲区的线程规则。

补充参数与容量：define rotary 的总大小最低 2048 bytes，单行预处理区最低且默认 1024 bytes，并不得大于总大小的一半；可选 stack offset 默认 256。分别测边界以下、合法边界、重复定义、资源不足和可选参数省略。用 $('')rotfree$('') 验证最大连续空闲块，用 $('')rotfreeall$('') 验证全部可用块，覆盖环绕前后及空闲容量变化。$('')delete all rotary$('') 单独在独占设备测全局删除，不能只用删除当前坐标系代表全局语义。

### O14 open prog 0 的 rotary 别名  P0  L2

依据：1283–1285。在同一已 define 的专用坐标系，分别走 `open prog 0` 和 `open rotary` 写入等价 F-ROT，再正确 close 和 list rotary。

预期：两者指向该坐标系的 rotary 缓冲区，不创建一个全局固定 Prog0。切换坐标系时不能错误操作另一 rotary 对象。恢复：两条路径均清理并核对 rotary 结构。

### O15 中断下载与孤立所有者恢复  P0  L3

依据：1169 的恢复用途；断线细节为项目故障测试。分别在 open 前、open 已确认后、部分行后、close 已发送但未收到结果时断开 A；B 检查是否仍有占用，再按事实决定恢复操作。

预期：库报告失败或结果不确定，不重放 open/程序行/close；不承诺断线自动 rollback。只有确认原所有者已失效且设备处于专用维护态，才考虑 `close all buffers`；之后 list/buffer 核对是完整、部分或已删除对象，部分对象不可执行。重新加载从头建立可验证版本，保留原失败记录。

### O16 全局清空与关闭的区别  P1  L3

依据：1166、1168–1169。专用设备预置固定程序和 rotary，完全退出所有运动程序并关闭 rotary；执行 `clear all buffers`，比较前后 buffer、固定 list、rotary 配置与可重新打开能力。

预期：固定 motion/PLC/kinematic 缓冲区被删除，rotary 内容清空但结构保留；与 O07 的仅关闭行为不同。另测 rotary 尚打开或运动仅挂起时前提不满足的拒绝/错误情况。恢复：按已验证备份恢复完整项目，不让清空测试污染其他组。

## 5 list 专项

以下默认 L0，但创建、运行或改变夹具时继承其 L1/L2/L3 等级。所有用于完整性比较的固定程序须先 close，比较期间禁止重载；PC/APC/rotary 测试另按状态设置执行。

### T01 三类固定程序回读  P0

依据：1235–1236。对 F-LINES 的 prog、plc、subprog 分别执行 `list prog {prog}`、`list plc {plc}`、`list subprog {sub}`。

预期：读回正确类型和编号的全部已编译内容，不因数值编号相同而串类型；无参数时正文无文本行号。读回不会执行程序，测试 P 哨兵保持不变。保存原始字节及由已编译程序建立的规范化基准。

### T02 正逆运动学回读  P0

依据：1234–1235。对两个测试坐标系分别执行 `&{c}list forward`、`&{c}list inverse`，再对另一坐标系重复，展开 T03 的全部参数形式。

预期：内容属于当前指定坐标系和正确方向；手册明确回读为 ASCII 编译表示，不恢复用户变量符号名或文本替换。不能拿原源文件做逐字节相等断言。

### T03 逗号 起始行 行数语义  P0

依据：1235–1236。用至少 12 条已确定可 list 的行，对固定程序和运动学分别展开以下矩阵。表中 `{obj}` 取 `prog {prog}`、`plc {plc}`、`subprog {sub}`、`forward`、`inverse`。

| 请求 | 预期 |
|---|---|
| `list {obj}` | 全部内容，不加文本行号 |
| `list {obj},` | 全部内容，显示从 0 起的文本行号 |
| `list {obj},5` | 从开头列 5 行，不是从第 5 行到结尾 |
| `list {obj},0,5` | 从第 0 行开始列 5 行 |
| `list {obj},8,3` | 第 8、9、10 行；第二参数是数量，不是结束行号 |
| `list {obj},{last},1` | 最后一条可报告行 |

先获得带行号的完整基准，再核对各片段内容、顺序、起止和条数。文本行号不等于 `N` 跳转/同步标签；一行多个语句不能误计多行。恢复：无设备写入。

### T04 编译表示与回读再加载  P1  L1

依据：1234–1237。加载含符号名、文本替换、注释与多语句的专用源文件；close 后 list。把回读中实际程序体与响应头、行号分离，经离线检查后加载到第二专用槽，再 list。

预期：符号和文本替换按编译后表示回读；不要求保留注释、源文件排版或原变量名。第二次回读在规定的规范化规则下语义一致。不得把 `prog …` 响应标题、`0:` 行号或 ACK 混入程序体；不能保证任意 list 原文直接粘贴即可重建原工程文件。

### T05 当前 PC 与调用层级  P0  L2

依据：1237。F-PC 用单步或可控停点稳定程序计数器，执行 `&{c}list pc`、`&{c}list pc,`、`&{c}list pc,2`；在子程序中重复。

预期：起点为下一条将被计算的程序行，可能领先当前机械正在执行的运动段；无逗号不加行号，有逗号显示行号，限行形式按手册包含程序名及适用调用层级。与带行号基准和实际 PC 对照，不以当前位置猜 PC。恢复：完全退出专用程序。

### T06 中止 APC 与 PC 的区别  P0  L2

依据：1155、1233–1234、1236。在 F-PC 已知计算位置执行 abort；分别读取 `list apc`、`list apc,`、`list apc,2` 和 `list pc`；另展开固定程序的 `list prog {prog},apc,2` 形式并记录固件支持。

预期：APC 指向发生 abort 时的计算位置；abort 后正常 PC 已回顶层程序开头，不能把两者当同一个位置。子程序场景核对调用链。自动故障中止只在可控台架追加验证；没有历史 APC 时的回复属于 T09 的观察项。

### T07 rotary 仅列尚未计算内容  P0  L2

依据：1238。F-ROT 在已关闭且尚未计算状态全量 list；运行到受控边界后停在可观察状态，再执行 `&{c}list rotary`、尾逗号、单行数和起点加行数形式。

预期：仅能回读尚未计算的行；已计算但其运动尚未完成的行也不能再回读。rotary 参数起点与最近计算位置相关，不能套固定程序绝对源文件行号。打开期间不满足 list rotary 前提。对 `apc` 形式保留实测结果；如存在固件差异，明确版本。恢复：完全退出、关闭并清理专用 rotary。

### T08 大列表 分包与末尾完整性  P0

依据：list 全量语义及项目传输契约。关闭 F-LONG 后，先建立可信完整回读基准；在直连 GPASCII、库原始请求、各 SDK 上分别全量 list。受控服务端另模拟任意字节拆包、跨 CR/LF/ACK 拆包、延迟及大于内部缓冲的响应。

预期：全部行按序且不重不漏，最后一行与协议边界正确；成功结果的字节数、行数和规范化内容与基准一致。超出输出限制时显式失败，不返回被截断的“成功”。硬件基准与模拟分包证据分别登记。

### T09 不存在对象与参数异常  P1

依据：1233–1238；未规定细节做版本记录。分别测试不存在的 prog/plc/subprog、未配置 forward/inverse、没有有效 PC/APC、未 define rotary、负行数、零行数、负起点、超末尾、数量越界、缺参数及多余参数。

预期：保存固件原始回应并区分合法空结果、拒绝和资源限制；不把任意空响应当成功，也不要求所有异常统一 Error 20。有效前缀之后的错误不得被解析器丢弃。紧接合法短查询仍能正确解帧，无跨请求残留。

### T10 关闭前后的状态边界  P0

依据：1169、各 open/list 条目。结合 O08/O12，比较 open 中、close 已发送未确认、close 已确认、空关闭已删除、非法行自动关闭后的 list；固定缓冲区与 rotary 分开执行。

预期：只有明确完成加载并关闭的完整固定程序能签为加载成功。遇到 close 结果不确定，先保留未知结论，再通过恢复与回读判断当前对象；不据后来的完整 list 篡改原请求的协议结果。不能让 list 的响应落入上一条 close 或下一条查询。

### T11 并发回读与对象变更  P1

依据：1235–1238、项目结果归属契约。对象稳定时 A/B 对两个不同固定程序并发 list；以不同常量标识验证归属。再在专用环境由 A 重载、B list 同一对象，记录返回的是哪个版本或错误。

预期：稳定对象并发无错归；变更期间手册没有快照承诺，结果应按实测完整性标注，不能声称获得原子版本快照。请求所属成员和 epoch 可追溯，后续短查询不含前一 list 残片。恢复：回到关闭的已知版本。

### T12 C ABI 与 SDK 完整结果复制  P0

依据：项目 ABI/SDK 契约，输入使用 T08 的 list。分别测试查询所需长度、空/不足/恰好/充足输出空间、重复复制、同步与异步结果、响应完成后请求句柄生命周期，以及取消/超时。

预期：所需长度及终止符约定符合 ABI；不足空间显式报告，重复读取不再次发送 list；原始结果不被局部正则捕获覆盖。取消/超时结果不得当成完整列表；请求与 Runtime 关闭后无句柄泄漏。分别记录 C、C++、.NET、Python 结果。

## 6 多线程与 GPASCII 独占专项

**强制架构约束：不允许两个应用线程使用同一个 GPASCII 通信线程。** 在一次有效会话期间，每条 GPASCII 通道只能有一个应用线程所有者；不同应用线程必须获得不同的控制器通信线程。不能用单条请求互斥、全会话排队或一个共享 Client 的串行队列代替通道独占。没有独立通道时必须在发送前明确失败，不能悄悄回退到另一线程已占用的通道。

这里的“应用线程”是实际提交在线指令的工作线程，“GPASCII 通信线程”是控制器端解释在线命令并持有 open、echo、Ldata 等上下文的线程。TCP 连接、SSH channel、Client 包装对象、member ID 任一单项都不能独自证明它们互不共享；应记录其关联及控制器端进程/线程身份。SDK 异步任务需通过明确的专用工作线程执行，不能因 Task 续体或线程池调度隐式改变通道所有者。

### MT01 用户指定的写入不串 buffer 场景  P0  L2

依据：用户线程独占约束；手册 1173–1174、1283–1284。仅在 Motor 1 可安全改变 ServoCtrl 的隔离台架上，使用专用 prog 1；若该对象被占用，先选替代测试对象并登记，禁止覆盖生产 prog 1。

步骤：

1. 登记应用线程 A/B 与各自不同的 GPASCII A/B；备份 Motor[1].ServoCtrl、prog 1 和相关配置。选择能辨认变化的安全初值，并禁止自动运行该程序。
2. A 发送 `open prog 1`，确认打开后设置同步屏障，保持 A 缓冲区打开。
3. B 经其独占通道发送 `Motor[1].ServoCtrl=1`，保存原始响应，再经 B 回读该元素。
4. A 在 B 完成后继续输入仅更新专用 P 哨兵的合法程序行，再由 A `close`。
5. 在关闭状态执行 `list prog 1`、带行号全量及分页回读，检查所有行；同时比较 B 写入前后元素值。

预期：B 的赋值在 A close 之前已在线执行，不依赖 prog 1 被运行；A 的程序只含 A 输入的程序体，**不含 Motor[1].ServoCtrl=1 的赋值语义**，也无来自 B 的其他语句。比较编译后目标元素及赋值，不能只做大小写敏感的原文搜索。A 能继续写入，B 不改变 A 的开闭状态。恢复：不运行该程序来验证隔离；直接恢复 ServoCtrl、原程序和配置，并核对。

### MT02 禁止跨线程使用通道  P0  L1

依据：用户约束。在受控 transport/testkit 记录实际发送次数：A 获得 GPASCII A 后，B 尝试通过 A 的 Client/Request 入口提交，分别在 A 空闲、open 中、close 后但会话未释放时测试。

预期：B 不得使用 GPASCII A。可以分配 GPASCII B 后执行，或在发送前明确拒绝；若拒绝应有可辨认错误且 NOT_SENT。即使互斥排队到 A close 之后再由 B 使用 A，仍判不满足独占约束。输出不能泄露 A 的局部上下文或将 B 的请求归给 A。

### MT03 同时打开不同缓冲区  P0  L1

依据：1279–1286 的全局打开互斥。A/B 已拥有不同 GPASCII；A open prog 1 后 B 尝试 open prog 2，另展开不同类型和不同坐标系。

预期：通道独占不等于设备支持同时打开多个程序缓冲区；B 的 open 仍按手册全局互斥被拒绝。B 随后在其自己的线程上做获准在线变量写入，不得写入 A 的 prog 1；A 的内容与所有权保持可验证。恢复由 A 关闭，B 重新 open 的新试验从干净状态开始。

### MT04 owner 与上下文交叉核对  P0  L1

依据：1119、1130、1175–1179、1193–1194、1229–1233、1300–1304。A/B 各自设置不同的 echo、#、&、L/R/D 哨兵值，交替与同时查询，并在 MT01 的 open 窗口重复 B 查询。

预期：两线程一直保持各自上下文；B 查询不能读到 A 的通信线程局部变量。共享的全局 P/结构元素应可互见，不能把“全局值相同”误当线程共享证据。独立身份与局部状态两类证据均需满足。

### MT05 close 与恢复指令不越权  P0  L3

依据：1169。A 打开，B 发普通 close，随后 B 发获准的全局恢复 close all buffers，两个试验独立复位。

预期：普通 close 不关闭另一线程的固定缓冲区；全局 close all buffers 可以跨线程关闭，但这是明确的设备全局恢复操作，不是 B 获得 A 通道所有权。需要独占维护条件，不能把恢复命令作为每次并发冲突的自动重试措施。rotary 规则仍按 O13 单独验证。

### MT06 边界交错与次数核对  P0  L1

依据：用户隔离要求及项目单次发送契约。用 barrier/event 精确安排 B 在 A 的 open 已发送未完成、open 已确认、程序体中间、close 已发送未完成四个窗口提交获准写入；每个窗口用独立夹具重复。

预期：B 始终从其独占通道发送且只发送一次；A 的 buffer 不含 B 写入。检查双方请求/结果与通道映射，无跨线程换主、响应错归、漏行、重复行。受控服务端覆盖所有窗口；实体台架只在安全可复现窗口取证，不以固定 sleep 证明发生交错。

### MT07 断线 取消与重新建连的所有者  P0  L1

依据：用户隔离要求、O15 与项目故障契约。A open 后断线/取消，B 保持自己的连接；A repair/重连生成新 epoch；另测旧 owner 线程退出及系统线程 ID 复用。

预期：B 不能接管 A 未完成会话；修复后的通道仍归明确所有者，旧队列不自动重放，旧句柄不因线程 ID 重用被新线程使用。是否残留设备缓冲区占用独立核对；恢复不得把 B 的正常指令送入孤立 A 会话。

### MT08 资源上限与读取路由  P0  L1

依据：用户隔离要求及显式池契约。配置只能提供少量通道，启动更多应用线程；分别在申请独立控制通道与选择 read pool 时测试。

预期：独立通道不足时明确资源不足，不借用其他 owner 的 GPASCII。带 Q/L/R/D、echo、默认 #/& 或 list pc/apc 等上下文的操作不能因负载均衡流入别人的通道；即使是全局只读请求，也不允许两个应用线程共享同一 GPASCII。物理通道与 owner 数量、配额和释放状态可解释。

### MT09 下载入口与 SDK 线程模型  P0  L1

依据：用户隔离要求及项目 ABI/SDK 契约。分别通过原始 get_response、文件/缓冲加载入口、C++、.NET、Python 启动 A 的 open→body→close，同时由 B 写获准在线元素；先受控服务端，再按 MT01 做台架复核。

预期：所有入口遵守同一独占规则；SDK 不能把两个工作线程封装到同一 GPASCII 后仅逐请求加锁。自动轮询、完成泵或健康探测不能在 A 的打开上下文插入在线指令。报告区分不发送命令的本地完成通知与真正会发网络命令的后台任务。任何入口无法满足时登记明确缺陷或未支持，不能用单线程测试代签。
### MT10 open plc 1 赋值 close list 的正向与并发回读  P0  L1

依据：用户指定操作；1169、1235–1236、1281–1283。前提：PLC 1 为专用槽且已 disabled，未处于 pause/step；A/B 拥有不同 GPASCII。两组 P 变量 `{pa}`、`{pa_next}` 与 `{pb}` 互不相同并已备份。若占用 PLC 1，选用登记的替代槽，不能覆盖用户 PLC。

先执行不带并发的正向序列，再重建初态执行带 B 干扰的同一序列：

| 次序 | 应用线程及通道 | 操作 | 检查点 |
|---|---|---|---|
| 1 | A 独占 GPASCII A | `open plc 1` | 确认已打开 |
| 2 | A 独占 GPASCII A | `P{pa}=111` | 该赋值进入 PLC 1，不立即写全局 P |
| 3 | B 独占 GPASCII B | `P{pb}=333`，或 MT11 中一条获准赋值 | B 操作在线执行；本行只用于并发版本 |
| 4 | A 独占 GPASCII A | `P{pa_next}=222` | 继续写入 A 的 PLC 程序体 |
| 5 | A 独占 GPASCII A | `close` | 确认关闭，不自动 enable PLC |
| 6 | A 独占 GPASCII A | `list plc 1` | 读回完整程序体 |
| 7 | A 独占 GPASCII A | `list plc 1,`、`list plc 1,0,2` | 核对带行号与分段内容 |
| 8 | B 独占 GPASCII B | 查询三个全局 P 测试变量 | `{pa}`/`{pa_next}` 仍为原值，`{pb}` 已为 333 |

预期：list 的编译表示包含 A 的两条赋值，不含 B 的赋值；条数按编译后的文本行基准核对。正向版本与并发版本的程序体规范化结果一致。PLC 1 始终保持 disabled，因此无需实际运行 PLC 来证明内容隔离。将同样的赋值与回读流程展开到 `open prog 1`；对于 B 的线程局部赋值，改由 B 回读其局部空间。恢复原 PLC/程序及所有变量值。

### MT11 B 线程多类赋值矩阵  P0  L1 或 L2

依据：用户要求及各变量/数据元素在线赋值条目。在 A 分别打开 `prog 1`、`plc 1` 的窗口中，逐行独立执行下表，每行重建 A 的相同夹具；A 在 B 前后写可识别程序行，最后 close 和完整 list。测试目标互不别名，避免 B 覆盖 A 的哨兵。涉及实际电机参数的行升级 L2。

| B 的赋值类型 | 模板 | B 结果核对 | A 的 buffer 核对 |
|---|---|---|---|
| 全局 P 单项 | `P{pb}=333` | B 及第三方获准只读通道可读到 333 | 不含此赋值 |
| 全局 P 表达式 | `P{pb}=100+233` | 在线求值得到 333 | 不含表达式或其编译等价语义 |
| 全局 P 列表 | `P{pb}..{pb_end}=444` | 预留范围内全部为 444 | 不因其他线程已 open 而将 B 的合法在线列表当作 A 的非法入缓冲行 |
| 坐标系 Q | 先在 B 选 `{c2}`，再 `Q{qb}=555` | 仅指定坐标系的测试 Q 改变 | 不含此赋值；A 的坐标系寻址不变 |
| 线程局部 L | `L{lb}=666` | B 局部值改变，A 同编号局部值不变 | 不含此赋值 |
| 线程局部 R | `R{rb}=777` | B 局部值改变，A 同编号局部值不变 | 不含此赋值 |

依据：1132–1134、1182–1185。先定义轴，再 define lookahead，测最低 1024 段、低于最低、重复 define 和内存不足；专用回溯轨迹测试 `\`、`<`、`>`。预期：数量为每电机段数，已存在需先 delete；快速停止、反向和恢复前向符合已配置回溯能力与缓冲历史，不能在无历史时期待无限回退。全局 delete 单独 L3，恢复原缓冲。

### C07 pmatch 与位置重匹配  P1

依据：1294。在已知缩放/偏置或已核对正运动学下执行 `&{c}pmatch`，前后比较轴起点与电机命令位置。预期：轴起始值重算匹配当前 motor 命令位置，不命令实际机械位移；无解配置清晰报告。恢复配置，记录轴坐标变化。

## 12 程序 PLC 与调试测试

### P01 begin run start 单步与前提  P0  L2

依据：1157、1160、1299–1300、1308–1314。F-PC 测 `b{prog}`/begin、`r`/run、`start{prog}`、s/step 和多步；覆盖无编号、有效标签、无程序、未闭环、HomeRequired 未满足和无解坐标系。预期：begin 仅设 PC，start 相当于 begin+run；StepMode 决定按运动或行单步，bstart/bstop 块保持其语义；前提不满足拒绝。无位置轴 dry run 很快，不能拿它验证机械轨迹时间。恢复完全退出。

### P02 Script PLC 生命周期  P0  L2

依据：1187、1195、1293、1306、1314。专用不触碰 I/O 的 PLC 覆盖 enable/disable/pause/resume/step plc，单编号、列表、范围及非法编号。预期：观察唯一测试计数和执行状态确认启停；pause 不等于 disable，暂停/单步期间不满足 open plc 前提。恢复原 disabled 状态并清理夹具。

### P03 C PLC 生命周期  P1  L2

依据：1186–1187、1195–1196。仅在有已审查测试 C PLC 时测 bgcplc 的列表启停和 rticplc 的启停。预期：正确后台/前台对象状态变化，Script PLC 接口不会误控制 C PLC。无测试模块标 BLOCKED 或经确认 N/A，不加载未知二进制。恢复基线。

### P04 临时编译执行 cpx cx  P1  L2

依据：1170–1171。用无运动、仅更新专用 P 哨兵的合法命令序列分别 cpx/cx，覆盖非法语法和所需资源被占用。预期：分别按 motion/PLC 执行环境运行；编译成功与完成执行分开判断，错误不误判成功。恢复哨兵及临时执行资源。

### D01 断点 设置 清除与全清  P1  L2

依据：1160–1162。F-PC 测 bpset 的行偏移、行内命令偏移与重复计数，停点用 list pc 交叉核对，再 bpclear；bpclearall 仅隔离设备 L3。预期：停在手册规定的计算位置，偏移不是 N 标签；清除后不再触发，Bp[] 清除状态符合手册。恢复全部测试断点。

### D02 共享内存字符串  P2  L1

依据：1315。在已分配用户共享内存准备短/长、终止符、末端边界夹具，执行 `string{offset}`。预期：偏移按 bytes，内容与终止条件符合手册，不越界读或把任意地址当字符串。非法偏移只在模拟或隔离环境负测。恢复内存。

## 13 保存与复位测试

本组全部 L3，不与运行中的机械、PLC 调试或外部下载并行。恢复成功是每个用例的一部分。

### F01 save 的持久化边界  P0

依据：1310–1311。使用可恢复工程文件夹具，确认程序作为文件下载，而非只用交互式 open 写入；改变获准 saved setup 值后 save，完成后复位并核对。

预期：配置和项目文件按手册保留；交互式 open 加载的程序不能据此自动认定会存入 Flash。固件 ≤2.4 或新版 SyncSave=0 的 ACK 只表示开始复制，不能据其允许立即断电；新版 SyncSave=1 完成 ACK 才有对应文件复制完成语义。逐记录固件与设置，恢复原工程并再次确认持久化。

### F02 fsave fload 及模板范围  P1

依据：1197–1199。备份自定义模板及保存文件，用仅查询专用变量的模板 fsave；改变变量后 fload。预期：仅恢复模板保存的范围，输出长格式与 echo 无关；FastSaveMode 的分区路径和 SyncSave 的 ACK 语义按手册分别记录。Acontis 即 Sys.EcatType=1 且实时网络活动时不执行 fsave，先具备独立停网维护条件。恢复模板、文件及变量。

### F03 无 ACK 应用复位  P0

依据：1128–1129。分别在独立恢复循环中发送一次 `$$$`、`$$$***`，记录发令、断线/静默、重新 readiness、只读探测及对象状态。

预期：两条指令均无确认字符，不以等待 ACK 超时认定未执行，不自动重发。$$$ 恢复上次保存配置；$$$*** 清活动程序及缓冲、setup 回默认，不改最后保存的 Flash 配置；其后 $$$ 可恢复该已保存配置。ready 与当前可查询只证明恢复后状态，原请求是否被库确认为完成须另有项目状态机证据。禁止在默认化期间 save，以免覆盖恢复依据。

### F04 reboot 的系统重启  P1

依据：1305。独占窗口发送一次 reboot，观察操作系统与 SSH 下线/上线，再检查控制应用。预期：包括 OS 重载，与只重置控制应用的 $$$ 不同；不自动重试，不仅凭 TCP 端口恢复就认定 GPASCII 已就绪。恢复原项目和所有测试状态。

### F05 空间不足 中断与未知结果  P1

依据：1311、1199 及项目故障契约。优先在受控文件系统/模拟环境测试 save 空间不足、fsave 模板缺失、响应途中断开；实体掉电只在专用硬件并具备恢复方案时做单独扩展。预期：空间不足保留明确错误与 FlashSizeErr，部分诊断输出不掩盖失败；结果未知不自动再次保存。恢复后比较持久配置及备份哈希，不能以单次重连代替持久化核对。

## 14 EtherCAT 测试

### E01 从站清单查询  P1  L0

依据：1191–1192。执行 `ecat slaves`、指定 0–7 网络和 -1 全部网络，覆盖空网络与非法索引。预期：逐从站解析物理位置、VID、产品码、alias、相对位置、状态与描述；厂商文本不可套单数字解析。与实际拓扑对照，多网络不混淆。

### E02 alias assign config 配置  P1  L3

依据：1188–1191。仅在 Sys.EcatType=0、符合各指令的停网前提和可恢复台架上，分别测 ecat alias、单从站/全网 ecat assign、ecat config。预期：alias 仅对支持软件设置的从站生效；assign 更新正确 Slave 结构与 SlaveCount，config 另更新 PDO/PDOMapping/SyncManager。对不适用 EcatType 不强行执行；记录明确 N/A。恢复原拓扑、alias 和配置。

### E03 EtherCAT 栈复位  P0  L3

依据：1191。安全状态发送一次 `ecat reset`，观察栈停止/初始化、从站重现、错误及 readiness。预期：应用实际重启总线接口，不能仅据一行启动日志就认定全部从站恢复运行；无自动重发，失败不误关闭其他独立健康控制通道。恢复原网络状态后再允许运动。

## 15 MACRO 测试

无相应硬件时须注明具体命令族 N/A 或 BLOCKED，不能用本机字符串测试签为真实 MACRO 通过。远端变量仅使用获准测试区，并备份两端；名称含 read 的复制指令也会写本地变量，不属于纯只读操作。

### X01 端口 环与线程上下文  P1  L1

依据：1260–1261。A/B 独占 GPASCII 分别查询 macroport、macroportstate 和 macroring，选择不同 ring，再 macroportclose 并复查。预期：ring 为线程上下文，范围 0–3；端口状态与分配/关闭一致，命令行 blocking 模式的超时按 100 servo periods 或非零 Macro.IOTimeout 解释。不得在其他 owner 的 GPASCII 上借用 MACRO 端口。恢复原选择并释放端口。

### X02 本地控制器 detect 与 init  P1  L3

依据：1257。完整连接测试环后，以已核对的 `macrocontrollerdetect` 查询环及本地 master，另测 macrocontrollerinit。预期：detect 结果匹配实际环；init 配置 synch master、其余 local master 和相关节点，不能把 init 当无副作用查询。手册标题存在拼写差异，按第 20 节处理。恢复配置与同步关系。

### X03 远端参数 查询 直接赋值与复制  P1  L2

依据：1254–1265、1272–1274。分别展开 macroauxiliary、macromaster、macroslave、macroringmasterslave 四族的直接查询、`=constant`、read 复制到本地、write 从本地复制到远端；短别名再按 NoShortCmds 测试。

预期：复制方向正确，ring/master/node/变量目标不混淆；查询与复制到本地的结果一致，写后独立回读。显式 ring/master/node 范围与压缩 node 编号不是同一概念，逐族按手册展开合法边界及越界；远端变量范围也按该族，不套本地 P 范围。远端超时不自动重试写操作。恢复远端与本地目标值。

### X04 Ring Order 全生命周期  P1  L3

依据：1266–1271。每个命令单独留证，不用一个“MACRO 通过”合并签收：

| 子项 | 命令 | 主要判据 |
|---|---|---|
| 发现和载入 | macroringorderdetect、macroringorderload、macroringorderstations | ringorder 文件、共享结构与站数一致；detect 包含写文件副作用 |
| 初始化与修复 | macroringorderinit、macroringorderrepair | 站号与环顺序按预期建立，repair 的恢复内容核对 |
| 备份与恢复 | macroringorderbackup、macroringorderrestore | 每站备份文件及还原目标正确；错误/缺文件清晰报告 |
| 验证 | macroringorderverify、macroringorderverifybackup | 分别比较环顺序内存基准与站参数备份，故意差异可辨认 |
| 保存和复位 | macroringordersave、macroringorder$$$、macroringorder$$$*** | saved/default 区别可验证；默认化后站号丢失及重新 init 有恢复方案 |
| 故障与时钟 | macroringorderclrf、macroringordersync | 清故障及全环同步的实际效果与影响范围明确 |

带站号指令分别测试指定单站及手册允许的默认/0 全站形式；只有完全隔离环可做全站测试。环路中断、文件错误及返回丢失分开注入；恢复后逐站核对，不自动重放远端复位和保存。

### X05 Station 通信与属性  P1  L3

依据：1275–1278。展开 macrostation/close、type/status/errors、clearerrors、enable 的读写、frequency 的读写、ringcheck 的读写。预期：进入 station 后后续命令重定向到目标站，关闭后返回本机；站号 1–254，允许的 0 广播按该指令单列。frequency 写可影响所有环与本地 gate，enable/clearerrors 也非纯查询。先读基线，再在台架写安全值并恢复；本机结果与远端站结果不能混为一谈。

### X06 从站控制命令与全局 clrf  P1  L3

依据：1169、1261–1262、1271–1272。在 macroslave{cmd} 与显式 ring/master/node 形式分别展开 CLRF、DATE、VERS、SAVE、$$$、$$$***，核对本地 clrf 的广播作用。预期：DATE/VERS 返回的是目标站身份；清错、保存及两类复位各有独立证据，未知写结果不自动重发。全局 clrf 不能冒充仅清单站错误。恢复所有站配置和端口状态。

## 17 通信库与多语言集成

本组是项目要求，不将其表述为控制器手册原生能力。MT 系列的线程独占约束适用于全部入口；当前 README 中的 control/读取池路由设计必须据此验收，不把现有串行准入设计自动认定为满足独占。

### L01 独占通道上的顺序与完整目标  P0  L1

每个应用线程仅使用自己独占的 GPASCII；同一 owner 的命令按接纳顺序执行。对电机/坐标系 helper 检查生成完整目标；原始多行 open/body/close 全程固定 owner 与 epoch。预期：线程内顺序正确，线程间不混用物理通道，拒绝/取消不留隐藏发送。用 MT01/MT10/MT11 的 list 内容取证。

### L02 受控服务端响应异常  P0  L1

对查询、list 和写入分别注入分包、延迟、远端错误、FIN/RST、SSH channel 关闭。预期：请求结果只发布一次，原始字节/错误归属正确；发送前取消为 NOT_SENT，发送后失去确认按项目契约保留可能已执行，绝不自动重放副作用命令。异常后各 owner 通过自己的新 epoch 恢复。

### L03 程序加载与维护屏障  P0  L1

对文件加载入口与原始 open/body/close 分别测试并发在线赋值、全局打开互斥、取消、加载错误、关闭失败；观察每条设备指令实际来自哪个 owner。预期：不会把维护入口或后台探测插入另一线程打开的缓冲区；EOF/进程返回不替代 close 和 list 内容验证。协议失败、部分加载、结果未知均不报告程序部署成功。

### L04 各语言与 ABI 一致性  P0  L1

在 C/C++/.NET/Python 重跑 T12、MT02、MT09 及获准的开闭/回读。预期：bytes/字符串、required length、错误、异步完成和释放行为一致，SDK 不隐式共用 GPASCII，不为等待完成发送额外在线命令；析构/取消不会误关闭另一 owner 的会话。共享 Runtime 不等于允许共享控制器通信线程。

### L05 非法输入与资源耗尽  P0  L1

在受控环境覆盖无效目标、NaN/Inf、溢出、超长命令、输出超限、并发配额及独占通道耗尽。预期：按 API 契约发送前拒绝或显式失败，不能静默截断/换目标/借用别人的 GPASCII；失败后配额和句柄可回收。只声明 helper 实际承诺的输入限制，不要求原始在线字符串自动实现全部控制器语法校验。

1. 适用 P0 全部 PASS，适用 P1/P2 按验收范围签收；没有前提的必需用例为 BLOCKED，不能算通过。
2. 线程独占、请求归属和完整内容为硬门槛。任何两个应用线程共用同一 GPASCII、B 语句混入 A 的 buffer、响应错归、静默截断或副作用自动重放均阻断验收。

4. 所有作用到设备的用例完成恢复核对；备份完整不等于已恢复。未完成恢复不能将整轮标为结束。
5. 每条附录指令及其参数变体有执行结果或有依据的 N/A。N/A 说明硬件/固件不适用，并经执行负责人确认；未执行不写 N/A 掩盖。

初始执行汇总为 NOT RUN；本文的覆盖索引仅代表计划已建立，不作为任何固件或平台的通过证明。
